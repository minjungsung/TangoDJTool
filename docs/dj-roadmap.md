# Tango DJ feature roadmap and progress

Updated: **9 November 2026**. Scope: validated changes on `main`; deployment and physical venue validation are separate.

**Feature inventory: 45 implemented features / 0 backlog features = 45 features.** There are also **12 resolved defects** and **5 validation tasks**, one complete and four open. The progress board counts all 62 tracked items: currently 58 complete and 4 open (94%). Each `F`, `B`, `D`, or `V` identifier counts once; acceptance criteria and evidence links do not add items. This is a scope count, not an estimate of engineering effort or a measure of live-event readiness.

Checked, struck-through features are implemented and have automated coverage. Their validation scope is stated below; completion does not certify a physical sound system. Four unchecked physical/endurance validation tasks remain open. **P0** means finish before depending on the change at an event; **P1** is the next product priority; **P2** follows the essential DJ workflow.

## Keeping this checklist accurate

Update a feature's status and evidence when it changes. Cross off a backlog item only after its acceptance criteria are met, and move it into the implemented section without changing its identity. Close a validation task only with recorded outcomes at its stated scope. Run `npm run roadmap` to regenerate the [progress board](dj-roadmap.html) from this checklist. The board counts all tracked items, including validation; keep the feature inventory distinct. Do not describe implementation, a simulated output test or an older report as a physical performance pass.
