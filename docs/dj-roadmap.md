# Tango DJ feature roadmap and progress

Updated: **9 November 2026**. Scope: the current local branch, not a claim about the deployed site.

**Feature inventory: 33 implemented features / 12 backlog features = 45 features.** There are also **5 validation tasks**, one complete and four open. The progress board counts all 50 tracked items: currently 34 complete and 16 open (68%). Each `F`, `B`, or `V` identifier counts once; acceptance criteria and evidence links do not add items. This is a scope count, not an estimate of engineering effort or a measure of live-event readiness.

Checked, struck-through features are implemented and have automated coverage. Their validation scope is stated below; completion does not certify a physical sound system. Unchecked validation tasks and backlog features remain open. **P0** means finish before depending on the change at an event; **P1** is the next product priority; **P2** follows the essential DJ workflow.

## Validation snapshot

- **Passed on this branch:** `npm test` — **88/88**; production/PWA build; complete default browser suite — **115/115**, including the expanded [performance browser suite](../tests/browser/performance.spec.js) — **20/20**. The subsequent normalization/fade loading fix has four additional unit regressions, eight focused performance browser checks and two passing production WebKit cases.
- **Production browser review:** 60 cases across desktop Chromium, phone Chromium and tablet WebKit. The full run recorded 56 passes and four failures from stale test navigation into a hidden Playback area. Both affected scenarios were corrected without weakening recovery assertions; the focused rerun passed **6/6** across all three projects, covering all four failures. All 60 distinct production cases therefore have passing outcomes on the final implementation.
- **Device-browser suite:** **17 passed, 1 expected skip**, zero failures. Chromium measured the actual generated-WAV fade signal. Automated WebKit's media-element analyser returned silence, so its local fade signal case is skipped; audible local fades there still need real-device listening. Device profiles are emulated, and YouTube envelope checks use a simulated official volume API.
- Both natural queue-end notification regressions pass in the full default run. Normalization/fade changes made while loading remain authoritative when playback starts.
- **Historical evidence:** the [October feature review](all-features-validation.md) and [device report](device-playback-validation.md) describe earlier revisions. Their old feature limitations and pass counts must not be substituted for current-branch validation.
- **Not yet verified:** actual headphone/room isolation, the venue system, real-device operating-system behavior, and current full-source/provider endurance. These remain explicit `V` tasks.

## Validation tasks

These five tasks validate existing features; they are not five additional product features. V01 is complete; the four physical/endurance tasks remain open.

- [x] ~~V01 · P0 · Complete current-branch browser regression~~ — **Complete; automated scope only.** Default browser suite 115/115; production review outcomes cover all 60 distinct cases after the six passing recovery reruns; device-browser suite 17 passed and one explicitly bounded WebKit signal skip. The loading-settings race has four passing regression tests in the 88-test unit suite. Analyser skips are not acoustic passes. Evidence: [browser cases](../tests/browser), [review configuration](../playwright.review.config.js), [device configuration](../playwright.devices.config.js).
- [ ] **V02 · P0 · Rehearse an actual venue program — Needs physical validation.** Acceptance: a DJ listens to the intended transfers, entrances, endings, gain/fade choices and cortina waits through the real system; verifies local codecs and any chosen online sources; records issues and corrections. Timer progress or musical metadata is insufficient. Evidence to extend: [playback procedure](../scripts/playback-review.mjs), [device report](device-playback-validation.md).
- [ ] **V03 · P0 · Verify two-output headphone isolation — Needs hardware validation.** Acceptance: actual headphones and room output remain separate during preview, live playback, source changes, permission denial, disconnect/reconnect and default-device changes; neither unverified nor failed routing sends preview to the room. Current [player tests](../tests/player.test.js) and [browser cases](../tests/browser/performance.spec.js) use simulated device identities.
- [ ] **V04 · P1 · Real-device power and transport behavior — Needs physical validation.** Acceptance: document supported phone/tablet/desktop browsers, screen wake-lock grant/release, headphone buttons/Media Session, interruption and resume behavior, and operating-system suspension limits. No background-playback guarantee without that evidence. [Device cases](../tests/browser/devices.spec.js), [wake/transport cases](../tests/browser/performance.spec.js).
- [ ] **V05 · P1 · Current-branch endurance and recovery — Not yet run.** Acceptance: a multi-hour isolated session checks local/provider transitions, queue edits, history, storage limits and network interruptions without stale callbacks or unintended starts; record the revision, elapsed time, failures and recoveries using portable evidence. Earlier source checks do not certify the current branch. [Soak](../scripts/soak.mjs), [DJ session procedure](../scripts/dj-session.mjs).

## Product backlog

These are enhancements not currently implemented. Existing partial capabilities are identified so they are not mistaken for missing functionality.

- [ ] **B01 · P1 · Import an existing DJ library and playlists — Backlog.** Current import reads audio tags or this app's JSON. Acceptance: documented CSV/M3U or supported-library mappings with a preview, orchestra/singer/style/year/BPM/cue fields where available, duplicate decisions and missing-file relinking; preserve source provenance and leave the active recording unchanged. Starting points: [metadata import](../src/main.js), [file identity](../src/file-sources.js).
- [ ] **B02 · P1 · Richer filters and sortable browsing — Backlog.** Current search/style/source/collection/played filters are implemented. Acceptance: combine artist/singer, year and BPM ranges, instrumental/vocal/unknown, source readiness and sorting without hiding unknown metadata incorrectly; clear/reset remains predictable. [Current library](../src/main.js).
- [ ] **B03 · P1 · BPM confidence and correction workflow — Backlog.** Current onset estimate and manual BPM are implemented. Acceptance: surface uncertainty, allow half/double correction and manual/tap review, and test on representative old recordings and expressive timing. Estimates must not claim beat matching or musical suitability. [Current analysis](../src/analysis.js).
- [ ] **B04 · P1 · Target end time and back timing — Backlog.** Current runtime/finish estimate is implemented. Acceptance: choose an event end time, compare known queued time plus gaps, explicitly account for unknown sources/manual holds, and suggest a reviewed final-tanda plan without automatically truncating the current recording. [Current runtime](../src/dj.js).
- [ ] **B05 · P1 · Manage multiple session histories — Backlog.** Current single history, CSV export and explicit reset are implemented. Acceptance: archive/select sessions, search history, annotate partial or mistaken starts, export selected sessions, and provide recoverable deletion; preserve the distinction between a start and a completed recording. [Current history](../src/session.js), [UI](../src/session-ui.js).
- [ ] **B06 · P1 · Multi-step Undo/Redo — Backlog.** Current one-step group Undo is implemented. Acceptance: a labeled recoverable stack for composition and metadata edits, predictable reload boundaries and no replay/rewind of active music while undoing preparation work. [Current Undo](../src/main.js).
- [ ] **B07 · P1 · Complete portable backup/restore — Backlog.** Current set JSON transfers metadata, with separate relinking and history CSV. Acceptance: a reviewed optional bundle includes required audio, sets, cues, preferences and archived history; verifies content identities and missing assets in a fresh browser. Original file handles must not be represented as portable files. Automatic device sync remains a separate design decision. [Storage](../src/storage.js), [history](../src/session.js).
- [ ] **B08 · P1 · Better measured loudness control — Backlog.** Current RMS/peak suggested gain is implemented; LUFS/true-peak normalization and limiting are absent. Acceptance: opt-in measured loudness and clipping headroom, representative transfer comparisons, an explicit bypass, and audible/measurement evidence on supported outputs. [Current analysis](../src/analysis.js), [gain path](../src/player.js).
- [ ] **B09 · P2 · More flexible master/cue routing — Backlog.** Current verified separate local preview is implemented. Acceptance: explicit master selection and supported channel/device mapping, segment audition where useful, consistent reconnection feedback, and hardware evidence before claiming isolation. It must work with existing shared-output blocking. [Current routing](../src/player.js), [settings](../src/performance.js).
- [ ] **B10 · P2 · Recording notes, tags and ratings — Backlog.** Current tanda notes and core recording metadata are implemented. Acceptance: optional recording-level transfer notes, energy/character tags and ratings survive export/import and feed library browsing without being treated as objective artistic scores. [Current metadata model](../src/model.js).
- [ ] **B11 · P2 · Reviewed batch metadata and cue edits — Backlog.** Current individual edits and bulk analysis are implemented. Acceptance: select a batch, preview changed fields, preserve unknown values unless explicitly replaced, undo the batch and keep the active clip unchanged. [Current editing](../src/main.js), [cue model](../src/model.js).
- [ ] **B12 · P2 · Readable event rundown export — Backlog.** Current machine-readable JSON and history CSV are implemented. Acceptance: export/print tanda order, artists/singers, cues, known duration, holds and uncertainty in a portable human-readable plan with no workstation paths. [Current program](../src/program.js), [runtime](../src/dj.js).

## Keeping this checklist accurate

Update a feature's status and evidence when it changes. Cross off a backlog item only after its acceptance criteria are met, and move it into the implemented section without changing its identity. Close a validation task only with recorded outcomes at its stated scope. Run `npm run roadmap` to regenerate the [progress board](dj-roadmap.html) from this checklist. The board counts all tracked items, including validation; keep the feature inventory distinct. Do not describe implementation, a simulated output test or an older report as a physical performance pass.
