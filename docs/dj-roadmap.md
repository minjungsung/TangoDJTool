# Tango DJ feature roadmap and progress

Updated: **9 November 2026**. Scope: validated changes on `main`; deployment and physical venue validation are separate.

**Feature inventory: 33 implemented features / 12 backlog features = 45 features.** There are also **12 resolved defects** and **5 validation tasks**, one complete and four open. The progress board counts all 62 tracked items: currently 46 complete and 16 open (74%). Each `F`, `B`, `D`, or `V` identifier counts once; acceptance criteria and evidence links do not add items. This is a scope count, not an estimate of engineering effort or a measure of live-event readiness.

Checked, struck-through features are implemented and have automated coverage. Their validation scope is stated below; completion does not certify a physical sound system. Unchecked validation tasks and backlog features remain open. **P0** means finish before depending on the change at an event; **P1** is the next product priority; **P2** follows the essential DJ workflow.

## Validation snapshot

- **Final automated checks:** `npm test` — **123/123**; production/PWA build; complete default browser suite — **153/153**. This includes [live workflow safety](../tests/browser/live-workflow-safety.spec.js) — **23/23**, [performance integration](../tests/browser/performance.spec.js) — **26/26**, [session recovery](../tests/browser/session-recovery.spec.js) — **3/3**, [external metadata](../tests/browser/metadata-import.spec.js) — **3/3**, and [offline hashing fallback](../tests/browser/hash-fallback.spec.js) — **3/3**.
- **Final production browser review:** **60/60** across desktop Chromium, phone Chromium and tablet WebKit, with zero failures. This run used the final production build after all source fixes. [Cases](../tests/browser/feature-review.spec.js), [configuration](../playwright.review.config.js).
- **Final device-browser suite:** **17 passed, 1 expected skip**, zero failures. Chromium measures the generated-WAV fade signal. Automated WebKit's media-element analyser returns silence, so its local fade signal case remains explicitly skipped; it is not an acoustic pass. Device profiles are emulated and provider/output-device responses are simulated where stated. [Cases](../tests/browser/devices.spec.js).
- **Reproduced defects:** failing baseline cases demonstrated reservation/readiness races, corrupt-history recovery, inconsistent import contracts and malformed real WAV tags before their fixes. Full regression also caught offline worker loading after content verification was strengthened; streamed fallback and identity checks now pass together.
- **Historical evidence:** the [October feature review](all-features-validation.md) and [device report](device-playback-validation.md) describe earlier revisions. Their limitations and counts must not be substituted for current validation.
- **Not yet verified:** actual headphone/room isolation, the venue system, real-device operating-system behavior, and multi-hour full-source/provider endurance. These remain explicit `V` tasks.

## Resolved defects

These items record reproduced defects and their regression evidence. They do not increase the product feature inventory.

- [x] ~~D01 · P0 · Apply local cue/fade gain before playback begins~~ — **Fixed; player regressions passed.** Saved resume and paused seek/resume apply the current envelope and normalized gain before native playback starts. Legacy malformed/extreme gain values are bounded defensively. [Player](../src/player.js), [cases](../tests/player.test.js).
- [x] ~~D02 · P0 · Keep YouTube permission guidance tied to an active attempt~~ — **Fixed; unit and browser regressions passed.** Load, resume and stalled-position retry establish a fresh attempt deadline; Pause, Stop, terminal states and errors clear pending guidance. Buffering remains a network wait. [Player](../src/player.js), [unit cases](../tests/player.test.js), [UI cases](../tests/browser/performance.spec.js).
- [x] ~~D03 · P0 · Isolate preview media errors from the master deck~~ — **Fixed; unit and browser regressions passed.** A preview error cancels pending cue work and clears cue status without opening master recovery or interrupting local master playback/history. Routing identities in tests are simulated. [Player](../src/player.js), [UI cases](../tests/browser/performance.spec.js).
- [x] ~~D04 · P0 · Publish Play next reservations only after saving~~ — **Fixed; delayed-save browser regressions passed.** Failed saves leave the original queue/audio aligned; Next, Stop, deletion and preparation edits during saving preserve the active occurrence. Ordinary queued saves include the current workspace when their serialized save begins. [Implementation](../src/main.js), [cases](../tests/browser/live-workflow-safety.spec.js).
- [x] ~~D05 · P0 · Cancel stale playback scopes and hand off the verified source~~ — **Fixed; 23 live workflow safety cases passed.** Pending library, tanda, cortina, full-program and candidate playback revalidate recording identity/cues and current scope composition. Deleted or edited scopes cannot start later. First-source handoff removes a second readiness read that could play old bytes under replacement metadata; normal Next/Retry still check their own source. [Implementation](../src/main.js), [cases](../tests/browser/live-workflow-safety.spec.js).
- [x] ~~D06 · P0 · Recover corrupt session history atomically~~ — **Fixed; unit and browser regressions passed.** Invalid names or storage quota errors preserve original saved bytes and UI state; a validated successful new-session save commits the replacement. [History](../src/session.js), [UI](../src/session-ui.js), [cases](../tests/browser/session-recovery.spec.js).
- [x] ~~D07 · P1 · Exclude ongoing music when a new DJ session starts~~ — **Fixed; unit and browser regressions passed.** Reset preserves delivered playback-request deduplication; provider callbacks, transport changes and Pause/resume do not log an unchanged active song. An explicit new Play request does log. [History](../src/session.js), [cases](../tests/browser/session-recovery.spec.js).
- [x] ~~D08 · P1 · Avoid copying history for duplicate transport callbacks~~ — **Fixed; meaningful unit regression passed.** Duplicate checks and session identity/count access avoid cloning/scanning retained event snapshots. The test verifies zero deep-history reads for duplicate UI callbacks; it does not claim measured continuous browser jank. [History](../src/session.js), [UI](../src/session-ui.js), [cases](../tests/session.test.js).
- [x] ~~D09 · P0 · Keep imported and manually edited metadata valid for playback history~~ — **Fixed; schema and UI regressions passed.** Reject blank/oversized identities, coerced array source identities, negative/nonfinite BPM and gain outside ±12 dB. Manual edits reject whitespace titles and invalid whole-number BPM before mutation; preparation names respect the 1,000-character model bound. [Model](../src/model.js), [unit cases](../tests/model.test.js), [UI cases](../tests/browser/performance.spec.js).
- [x] ~~D10 · P0 · Verify retained local audio after same-ID set imports~~ — **Fixed; real hashing browser regressions passed.** Stored copies and connected originals always verify a known content hash, including equal-size/equal-timestamp files. A conflicting imported hash blocks playback and preview while retaining recoverable audio; identical content remains usable/relinkable. [File sources](../src/file-sources.js), [cases](../tests/browser/performance.spec.js).
- [x] ~~D11 · P0 · Normalize external tags before saving recordings~~ — **Fixed; five unit and three browser regressions passed.** Real WAV and provider metadata use typed, trimmed, bounded text and usable title fallbacks; invalid numeric tags become unknown. Original audio tags remain in the stored source. Playback history and reload succeed for oversized/whitespace metadata. [Normalization](../src/metadata.js), [unit cases](../tests/metadata.test.js), [browser cases](../tests/browser/metadata-import.spec.js).
- [x] ~~D12 · P0 · Keep verified local playback usable when workers cannot load offline~~ — **Fixed; streamed hash and browser regressions passed.** Worker construction/load failures fall back to the page's already loaded SHA-256 implementation, reading at most 1 MiB at a time. [Hashing](../src/stream-hash.js), [unit cases](../tests/hash.test.js), [browser cases](../tests/browser/hash-fallback.spec.js), [offline session case](../tests/browser/workspace.spec.js).

## Continuing review

An enabled daily review runs every 24 hours. The first next run was scheduled for **10 November 2026 at 19:13 KST**. Reviews fetch `main`, preserve unrelated edits, audit existing DJ workflows and the backlog, reproduce concrete defects, implement a focused improvement, run appropriate checks, update this checklist/board, and commit/push validated task-owned changes directly to `main`. Additional reviews continue when requested; a completed automated item never certifies untested venue hardware.

## Keeping this checklist accurate

Update a feature's status and evidence when it changes. Cross off a backlog item only after its acceptance criteria are met, and move it into the implemented section without changing its identity. Close a validation task only with recorded outcomes at its stated scope. Run `npm run roadmap` to regenerate the [progress board](dj-roadmap.html) from this checklist. The board counts all tracked items, including validation; keep the feature inventory distinct. Do not describe implementation, a simulated output test or an older report as a physical performance pass.
